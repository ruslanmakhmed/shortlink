# План работы: как довести проект до сдачи

Файлы в `shortlink/` готовы и проверены линтерами. Три вещи за вас не сделать: **история Git за месяц**, **прогоны на стендах** и **понимание на защите**. План ниже закрывает все три. Важно: не заливайте всё одним коммитом, условие допуска №3 это сразу провалит. Переносите файлы в свой репозиторий частями, по неделям, через ветки и запросы на слияние (MR/PR). Каждую часть сначала запустите на стенде.

Пароль Ansible Vault лежит в `shortlink/ansible/.vault_pass` (в Git не попадает). Сохраните его в менеджер паролей или смените: `ansible-vault rekey inventory/group_vars/all/vault.yml`.

## Неделя 17 → тег v0.1.0

| Ветка | Что переносите | Коммиты (пример) |
|---|---|---|
| (прямо в main, первый коммит) | `.gitignore`, пустой README | `chore: add .gitignore` |

На стенде Docker: `./scripts/bootstrap.sh`, проверка up → ссылка → down → up. Тег: `git tag -a v0.1.0 -m "..." && git push --tags`. Отчёт в чат.

## Неделя 18 → тег v0.2.0

| Ветка | Что переносите |
|---|---|
| `feature/ansible-role` | `ansible/` (сначала роль без vault, отдельным коммитом — vault и basic auth) |
| `feature/ci` | `ci/`, `.gitlab-ci.yml`, `.yamllint` |

На стенде Ansible: впишите реальные адреса и пользователя в `inventory/hosts.yml`, два прогона подряд (`changed=0`), `--check`, `ansible-lint`. **Если стенд пускает только под root**, первый прогон под root закроет root-вход. Сначала убедитесь, что пользователь `deploy` с вашим ключом создан, и дальше работайте под `-e ansible_user=deploy`. **Если ufw или systemd на узлах не работают** (узлы-контейнеры), поставьте `shortlink_firewall_enabled: false` и объясните это в README.

В одном из MR (лучше `feature/ansible-role`) напишите своё ревью: что сделано и почему так (идемпотентность, handlers с listen, drop-in для sshd, почему cron).

## Неделя 19 → кластер работает

| Ветка | Что переносите |
|---|---|
| `feature/k8s` | `k8s/` (частями: namespace+configmap → postgres → app → ingress) |
| `feature/deploy-stage` | стадия deploy в `run-stage.sh`, если переносили её отдельно |

На стенде Kubernetes: `k3d cluster create --config k8s/k3d-cluster.yaml`, **первым делом** `docker ps --filter name=registry`. Имя контейнера реестра должно совпасть с `CLUSTER_REGISTRY` (`shortlink-registry:5000`). Если k3d добавил префикс `k3d-`, запускайте с `CLUSTER_REGISTRY=k3d-shortlink-registry:5000` и поправьте дефолт в `run-stage.sh` и `k8s/kustomization.yaml`.
Проверки: `kubectl delete pod postgres-0` → ссылка работает; обновление и откат по RUNBOOK с записью в «Журнал выполнения». Снесите кластер и поднимите заново.
